# Dépannage

[← Retour au README](../README.md)

| Symptôme | Piste |
|---|---|
| Ventilateurs ARGB (branchés sur la carte mère ou un hub) éteints | Un bandeau « connecteurs ARGB à configurer » apparaît : **Configuration automatique** leur donne 60 LED chacun (assez pour 3 ventilateurs ou une bande ; déclarer trop de LED est sans risque). Pour affiner : Appareils → la carte mère / le contrôleur → « Zones et canaux ». OpenRGB ne peut pas deviner ce nombre ; il est mémorisé (et sauvegardé dans config.json). |
| RAM (ou carte mère SMBus) absente après une nouvelle installation | Par prudence, cet éclairage est désactivé par défaut : Réglages → Accès matériel → **Éclairage de la RAM** (ou **Cartes mères pilotées par le SMBus**), après avoir lu l'avertissement. Le moteur redémarre et les détecte. |
| « RAM laissée de côté : … est ouvert » | Un autre logiciel RGB utilise le bus de la RAM : deux programmes qui y écrivent en même temps peuvent abîmer les barrettes. Fermez-le (vérifiez aussi la zone de notification et les services qui démarrent avec Windows, comme iCUE ou Armoury Crate) : TuxRGB reprend la RAM tout seul dans les 5 secondes. |
| Lumière réseau introuvable | Même réseau local que le PC (pas un réseau invité). **Govee** : « LAN Control » activé pour la lumière dans Govee Home. **Yeelight** : « Contrôle LAN » dans l'application Yeelight. **Hue** : appuyez sur le bouton rond du pont puis « Associer » dans les 30 s. **Nanoleaf** : maintenez le bouton marche 5 à 7 s (voyants qui clignotent) puis « Associer ». **Kasa** : les modèles Tapo et les firmwares récents (protocole KLAP) ne répondent plus en local. Si la recherche ne trouve rien, l'adresse IP (visible dans votre box ou l'application du fabricant) s'ajoute à la main. |
| RAM absente | Réglages → Accès matériel → « Copier le rapport matériel » : le rapport (aussi enregistré dans `~/.local/state/tuxrgb/rapport-materiel.txt`) liste le contrôleur SMBus, les bus I2C, les pilotes SPD et le journal de détection, avec des pistes. |
| RAM absente, contrôleur SMBus « pilote=aucun » (Gigabyte AM5…) | Le firmware réserve le SMBus. Bandeau d'accueil ou Réglages → Accès matériel → **Débloquer l'accès SMBus** : ajoute `acpi_enforce_resources=lax` avec la méthode de votre distribution (voir [SECURITE.md](SECURITE.md)) et, en DDR5, écarte le pilote de sonde `spd5118` (`/etc/modprobe.d/tuxrgb-spd5118.conf`), puis redémarrer. Rien n'est modifié si l'accès fonctionne déjà. « Réinitialiser les permissions » annule tout. Prudence avec la DDR5 (risque de corruption SPD signalé par OpenRGB). |
| « Règles udev en double » | Un `60-openrgb.rules` dans `/etc` masque celui de la distribution : « Corriger » le remplace par un complément (l'original est sauvegardé et remis par « Réinitialiser »). |
| Effets aux couleurs du bureau | Statique / Respiration : « Synchroniser avec l'accent KDE / GNOME / COSMIC ». Effets multicolores : « Palette Système Harmonieuse » (dominante = accent exact, variante, nuance harmonisée). Un changement d'accent passe en fondu sur toutes les LED. |
| Le lancement échoue sans fenêtre | Le journal de chaque lancement est dans `~/.local/state/tuxrgb/tuxrgb.log` (le précédent dans `tuxrgb.log.old`), panics compris. Si le rendu GPU plante à l'ouverture de la fenêtre, le lancement suivant passe automatiquement en rendu logiciel. |
| Pas d'icône dans la zone de notification sous GNOME | Installer l'extension « AppIndicator and KStatusNotifierItem Support ». |
| Synchro écran : rien ne se passe | Accepter le partage d'écran dans la fenêtre du portail ; le jeton est mémorisé ensuite. |
| Interface lente sur une machine sans GPU | Réglages → Performances → Rendu « Logiciel », ou `tuxrgb --software-render`. |
| Luminosité | Appliquée par TuxRGB lui-même, en même temps que la correction des couleurs des LED, avant l'envoi à OpenRGB : elle agit pareil sur la RAM, les ventilateurs, la souris, le clavier et la carte mère, sans changer la teinte. La luminosité matérielle reste au maximum. |
| Journal du moteur OpenRGB | `~/.local/state/tuxrgb/openrgb-server.log` |
| Ventilation : « Aucun ventilateur trouvé » (Linux) | Le pilote du contrôleur de la carte mère n'est pas chargé. « Activer » essaie `nct6775`, puis `it87`, puis `it87` avec son option `ignore_resource_conflict=1` (cartes Gigabyte dont le firmware réserve les ports du capteur) et le garde pour les démarrages suivants s'il fonctionne. Le rapport matériel (section « Ventilation ») liste les puces, les ventilateurs et leurs modes. |
| Ventilation : la vitesse ne change pas (Linux, cartes Gigabyte) | Le mode manuel du pilote `it87` est ignoré par la puce ITE IT8689E. Depuis la 3.2.1, le service corrige lui-même le registre de la puce : Ventilation → « Mettre à jour » pour installer le nouveau service. Avec Secure Boot, le noyau interdit cet accès : les ventilateurs restent alors à la carte mère (« Refusé par le pilote »). |
| Ventilation : un ventilateur « Refusé par le pilote » | Le pilote n'accepte pas le mode manuel sur ce connecteur : la carte mère le garde. |
| Ventilation : « Mettre à jour le service des ventilateurs » | Le service installé vient d'une autre version de TuxRGB : il continue d'appliquer vos réglages, « Mettre à jour » installe celui de cette version (mot de passe administrateur). Journal du service : `journalctl -u tuxrgb-fans`. |
| Ventilation : vitesses qui changent toutes seules | Un autre logiciel pilote aussi les ventilateurs : un seul à la fois (Linux : `fancontrol`, CoolerControl, fan2go ; Windows : FanControl, Gigabyte Control Center / SIV, Armoury Crate, MSI Center). Laissez ces ventilateurs sur « Carte mère » dans TuxRGB, ou fermez l'autre logiciel. |
| Ventilation (Windows) : « Mode administrateur nécessaire » ou aucun ventilateur | Réglages → Accès matériel → Configurer l'accès (pilote PawnIO + mode administrateur), puis « Détecter ». Seuls les contrôleurs ITE et Nuvoton sont pris en charge ; sur les cartes Gigabyte à deux contrôleurs, ceux du second sont affichés en lecture seule. |
| Windows : la mise à jour depuis l'application relance l'ancienne version | Corrigé dans l'installateur de la 3.2.2 (il attend que TuxRGB soit fermé). Depuis une version plus ancienne, installez la nouvelle à la main depuis les Releases : réglages, OpenRGB, PawnIO et mode administrateur sont conservés. Journaux Windows : `%LOCALAPPDATA%\tuxrgb\tuxrgb.log`. |
